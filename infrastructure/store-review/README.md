# Isolated store review service

This Compose project is **only** for Apple and Google reviewers. It starts a fresh PostgreSQL database, reachable only on the private Docker network, and a limited version of the actual release API. There is no shared database, enrollment in the public sensor network, public map, raw audio, administration or access to field-test devices. The normal store app has no default server. Keep the service running while the stores review the app and any resubmissions.

1. Use a fresh project directory/Compose project. Verify the requested loopback port and bridge subnets are free. Keep environment and secrets outside Git: generate different random values for `REVIEW_DB_PASSWORD` (URL-safe) and `REVIEW_APP_SECRET`. Set `REVIEW_ACCOUNTS_PATH` to a JSON object mapping two synthetic addresses at `example.org` to separate random passwords (at least 24 characters). Keep it in a private directory and readable by the container's service user. The loader refuses to start with any other database name or an invalid account list.
2. Build and start `compose.yaml` with the operator's private env file. PostgreSQL has no host port. Publish only the API loopback port to the project's dedicated HTTPS hostname. Accept forwarded headers only from the trusted proxy hop, and never enable request/body logging. Verify the exact HTTPS host from a client outside the server, including the API base path `/api/v1`.
3. Provision each reserved account once through the registration endpoint. The real backend hashes the password. Verify both logins before entering each store's **own** credentials in its private review form. Do not provision on application startup: a restart must not undo a deliberate account deletion. To test destructive flows, use only one of these synthetic accounts and deliberately recreate an empty account before giving its details to a reviewer. No Google reviewer must create an account.
4. Check health, login, registration rejection for other addresses, the web deletion form and bearer-only sensor enrollment. There are no public/admin/snippet routes. The regular self-hosted product removes an account and associated active data; a review database is never a production or field-test backup. The review service deliberately exposes a subset of the real API. No claim about availability for ordinary users follows from this test.
5. Remove only this hostname route and the named review Compose project after its retention/operational period ends. Do not delete a database/volume without separately confirming its scope. Avoid storing credentials or device identifiers in project docs.
